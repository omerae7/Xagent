# معماری X Agent

این سند سازوکارهای اصلی را توضیح می‌دهد و مشخص می‌کند هر الزام مشخصات در کجای کد پیاده شده است.

## ۱. اجزا و جریان داده

| جزء | مسیر | نقش |
|---|---|---|
| API | `services/api/xagent_api` | احراز هویت، REST، SSE رویدادهای زنده، پروکسی WebSocket دسکتاپ، STT/TTS |
| Worker | `services/worker/xagent_worker` | مصرف صف Runها، زمان‌بند روتین‌ها، صندوق رویداد، تلگرام، رویا، نمونه‌برداری بار سیستم |
| هسته ایجنت | `packages/agent_core/xagent_agent` | چرخه اجرا (`pipeline.py`)، مسیریاب (`classifier.py`)، انتخاب مدل (`model_select.py`)، Harness، Stop-Loss، یادگیری، رویا |
| حافظه | `packages/memory/xagent_memory` | لایه‌ها (`store.py`)، حافظه چت (`working.py`)، کانتکست با بودجه (`context.py`)، Undo (`revisions.py`) |
| ابزارها | `packages/tools/xagent_tools` | ابزارهای داخلی، محیط ایزوله (`sandbox.py`)، MCP (`mcp_client.py`)، نصاب (`installer.py`) |
| دسکتاپ | `infra/desktop` | XFCE + Chromium + Telegram Desktop، دیمن کنترلی `agentd.py` و پل MCP |

**مسیر یک پیام چت:** `POST /api/chat/send` ← ذخیره پیام و ساخت `Run` ← `XADD xagent:runs` ← Worker (`XREADGROUP`) ← `AgentRunner.execute` با قفل اتمیک `run:{id}` ← مراحل با Checkpoint در `runs.state` ← انتشار `run.step` و `message.created` روی Redis Pub/Sub ← SSE به پنل.

فرمان‌های قطعی (`وضعیت`، `توقف همه`، `ادامه همه`، `آندو`) همان لحظه در API و بدون مدل اجرا می‌شوند تا حتی وقتی Worker مشغول است توقف اضطراری فوری باشد.

## ۲. چرخه اجرا (`pipeline.py`)

1. **دریافت:** پیوست صوتی با نقش STT به متن تبدیل می‌شود؛ تصاویر یا مستقیم به مدل بینایی‌دار داده می‌شوند یا ابتدا با نقش «چشم» توصیف می‌شوند.
2. **مسیریابی قطعی:** `classify()` پیچیدگی (trivial/simple/complex)، ریسک، گروه‌های ابزار و لایه‌های حافظه را بدون LLM تعیین می‌کند.
3. **هدف‌سنجی و برنامه‌ریزی:** فقط برای کارهای پیچیده/حساس و با مدل مدیر (JSON). اگر ابهام حیاتی باشد، به‌جای حدس سؤال پرسیده می‌شود.
4. **حافظه گزینشی:** `build_context()` با بودجه متناسب با پنجره کانتکست مدل؛ لایه رویدادی هرگز در کانتکست نیست و فقط از طریق ابزار `episodes_query` کوئری می‌شود.
5. **پرامپت سازگار با کش:** بخش ثابت (هویت، اصول امنیتی، خلاصه Harness) جدا از بخش متغیر (زمان، حافظه، هدف) ارسال می‌شود تا کش پرامپت ارائه‌دهنده بیشترین اثر را داشته باشد.
6. **اجرا:** حلقه ابزار؛ هر فراخوانی ابتدا از Harness می‌گذرد. ابزار می‌تواند در حین اجرا دسته را ارتقا دهد (مثلاً تایپ در فیلد رمز ← دسته «لاگین»).
7. **اعتبارسنجی:** قطعی برای کارهای ساده؛ برای کارهای پیچیده، مدل ارزیاب بر اساس شواهد واقعی ابزارها. یک دور بازیابی با راهنمای اصلاح.
8. **یادگیری:** ثبت رویداد، تجربه (موفق/ناموفق)، ارزیابی دوره آزمایشی یادگیری‌های استفاده‌شده و انتقال نکات مهم کارفرما.

## ۳. Harness

`harness.evaluate()` کاملاً قطعی است. حالت‌ها: `auto`، `ask`، `conditional` (شروط `allow`، `deny`، `ask_actions`، `max_amount`)، `forbidden`. دسته‌های `payment` و `system_update` هرگز خودکار نمی‌شوند. حالت `ask` یک `Approval` می‌سازد، Run را در وضعیت `waiting_approval` با Checkpoint نگه می‌دارد و پس از تصمیم (پنل یا پیام «تایید xxxx» در تلگرام) دوباره در صف قرار می‌گیرد.

## ۴. مدیریت سه‌لایه حلقه

1. `LoopController`: امضای (ابزار + آرگومان‌ها) و خطاهای پیاپی را می‌شمارد ← `change_strategy` ← `escalate` (تعویض زنجیره مدل به مدیر و سقف گام پیچیده) ← `abort` (توقف کنترل‌شده).
2. `StopLossEnforcer`: قبل از هر فراخوانی مدل و ابزار؛ سقف هزینه/توکن تسک، روزانه/ماهانه (کش‌شده در Redis)، گام (تعداد اقدام)، زمان اجرا، `STOP_ALL` و لغو کارفرما. نتیجه: `paused` با Checkpoint و امکان «ادامه با بودجه بیشتر».
3. روتین‌ها: Lease اتمیک Redis با TTL، رد نوبت در صورت اجرای فعال، مدارقطع‌کن (`closed` ← `open` ← `half_open`) و هشدار ویژه برای روتین‌های زمان‌حساس.

## ۵. حافظه و Undo

- جست‌وجوی ترکیبی: `tsvector` روی متن نرمال‌شده فارسی (تابع SQL `xa_normalize`: یکسان‌سازی ی/ک، ارقام، حذف اعراب و نیم‌فاصله) + `pg_trgm` + بردار HNSW، ادغام با Reciprocal Rank Fusion.
- جاسازی پیش‌فرض محلی (`local-hash-v1`، Feature Hashing روی n-gram) برای اجرا روی هر سخت‌افزار بدون هزینه؛ قابل تعویض با مدل Embedding ارائه‌دهنده. ستون بردار ۷۶۸ بعدی است و بردارهای کوتاه‌تر با صفر پر می‌شوند (شباهت کسینوسی حفظ می‌شود).
- `memory_revisions`: هر ایجاد/ویرایش/تغییر وضعیت با `before`/`after`. `undo_revision` تغییرات جدیدتر همان موجودیت را آبشاری برمی‌گرداند. `observe_probation` معیارهای پایه را با مشاهده مقایسه و در صورت پسرفت Undo خودکار می‌کند.

## ۶. ایزوله‌سازی ابزارها و دسکتاپ

- `DesktopSandbox`: همه فرمان‌ها، نصب‌ها و سرورهای MCP داخل کانتینر دسکتاپ (کاربر `agent`، بدون اسرار). سرورهای MCP از نوع stdio در دیمن پایدار نگه داشته و از طریق Streamable HTTP در دسترس Worker قرار می‌گیرند؛ `initialize` تکراری کش می‌شود.
- `LocalSandbox` (پروفایل lite یا بدون دسکتاپ): فرایند با محیط حداقلی، `RLIMIT_AS`/`RLIMIT_NOFILE` و پوشه کاری جدا.
- VNC: دو سرور x11vnc (فقط‌مشاهده و کنترلی) روی localhost کانتینر؛ websockify فقط روی شبکه داخلی؛ API پس از احراز کوکی پروکسی می‌کند و حالت کنترلی فقط هنگام Takeover باز است.
- مرورگر: Chromium با پورت CDP محلی و socat برای شبکه داخلی؛ Playwright با `connect_over_cdp` و شماره‌گذاری عناصر قابل تعامل (`ref`) برای کلیک پایدار.

## ۷. انحراف‌های آگاهانه از مشخصات (با دلیل)

| مشخصات | پیاده‌سازی | دلیل |
|---|---|---|
| به‌روزرسانی از داخل پنل | فایل درخواست + سرویس systemd میزبان | دادن سوکت داکر به کانتینر معادل دسترسی root است؛ این روش امن‌تر است و پشتیبان + Rollback دارد |
| ابزار نصب‌شده در «محیط ایزوله» | اجرا داخل کامپیوتر ایجنت | Worker که به دیتابیس و کلیدها دسترسی دارد هرگز کد شخص ثالث اجرا نمی‌کند |
| جاسازی برداری | محلی به‌صورت پیش‌فرض | اجرا روی هر سخت‌افزار و شبکه محدود بدون هزینه؛ قابل ارتقا به مدل API |
| مکالمه صوتی زنده | تشخیص گفتار مرورگر (VAD) + STT + اجرای ایجنت + TTS | مستقل از ارائه‌دهنده و قابل استفاده از ایران؛ به API بلادرنگ خاص یک شرکت وابسته نیست |
| شمارش «گام» در Stop-Loss | تعداد اقدام (فراخوانی ابزار) | قابل‌فهم‌تر برای کارفرما؛ هزینه و توکن مدل جداگانه سقف دارند |
